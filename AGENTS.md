# Agent instructions

- Before running everyapp, read the everyapp skill: `packages/cli/skills/everyapp/SKILL.md`; before building or changing an app, the build-every-app skill: `packages/cli/skills/build-every-app/SKILL.md` (they ship in the CLI package; `everyapp create` links them into each new app from `.agents/skills/<name>` and `.claude/skills/<name>` to `node_modules/everyapp/skills/<name>`). The skills are short routers: a few rules that rarely change and pointers to the agent docs. Put new detail on a docs page, not in a skill, since an app's skills only change when it upgrades the CLI.
- The references written for agents (commands and flags, the `--json` protocol, error codes, `everyapp.config.ts`, what an app receives from the Gateway, deploys, secrets, development, email, MCP and agent tools, Cloudflare Access, building an app and its patterns, and a setup guide per integration under `setup/`) are `landing-page/content/agent/**/*.md`, served at https://everyapp.com/llms.txt and bundled into the CLI package for `everyapp docs <page>`. The flag and error-code reference and `setup/providers.md` are generated from the CLI (`pnpm -C packages/cli docs:update`). Answer "how do I" questions from them; the user docs in `landing-page/content/docs` stay short and are for the person.
- Inside this checkout, run everything with `pnpm everyapp` (the checkout's own CLI, which builds the Gateway from source). `npx everyapp` / `npm i -g everyapp` is the published package, for people without a clone; don't use it here.
- Live tests run only when Ben asks for that specific run. A live test is anything that deploys to or changes a real Cloudflare account: the `*.live.test.ts` files (`EVERYAPP_LIVE_*`), and end-to-end runs on the test accounts `loop-1` and `loop-2`. Never start one yourself, schedule one, or repeat one. Stop at "ready for a live check" and ask. Unit tests, scoped vitest and local `everyapp dev` are fine.
- Before a pull request that touches the perimeter, identity, Cloudflare Access, OAuth, tokens or secrets, run `pnpm security-review` (the security-review skill). Other changes don't need it. The boundaries it reviews against are `docs/security.md`.
- Keep UI = CLI = MCP parity: anything a person can do in the Gateway's UI can be done with a CLI command and a Gateway MCP tool too. A new UI action adds its row to the matrix in `docs/design/2026-10-agent-parity.md`, which `packages/cli/src/docs/parity.test.ts` checks.
- A change doesn't owe paperwork: no new event type, `docs/security.md` row or TODO.md note just because an admin action was added. Update the docs, skills and messages the change makes false.
- `TODO.md` holds open questions and steps waiting on Ben, one line each where possible. Delete an item once it is decided or done; git keeps the history.
- **Never vendor the SDK or CLI into an app** (no `vendor/*.tgz`, no `file:` or `link:` specifiers committed in an app's `package.json`). Apps pin a published version (`pnpm pack-for-app <app> --npm <version>`). To try unreleased platform code in an app, `pnpm link` the checkout's `packages/sdk` and `packages/cli` locally and don't commit the override; to ship it, release (`pnpm release patch`, then `pnpm release publish` from main; Ben runs it, `.github/RELEASE.md`) and pin that. Runbook: `docs/runbooks/app-releases.md`.
- **The Mac desktop app is `apps/desktop`** (Every App for Mac: Electron, its screens in `apps/desktop/ui`, the Swift helper in `apps/desktop/mac`). Scribe (meeting notes) is its first feature; feature backends live in their own repositories. Read `apps/desktop/README.md` before changing it: its names in `identity.json` are permanent, and backend app ids belong only in `src/shared/features.ts`.
