# Cold read (2026-10-24)

Written 2026-10-24, the Saturday before the launch on Monday 2026-10-27. Two outsiders read `main` at `65fcac70` (the worktree `t3/overnight-cold-read`, the site served locally at `http://127.0.0.1:5179`, the built CLI, the starter, the skill) with nothing but what a stranger has: the skeptical first user, in five guises (a technical founder, a non-technical founder, the same founder at a terminal logged out of Cloudflare, their coding agent following the README prompt, and the founder opening the app `create` made), and the outside security researcher, read-only and unauthenticated, who mapped the surface from the source, ran 154 probes against the dogfood install (`everyapp.team` and its four app hosts) plus one verification request and five DNS lookups, read the public copy the push would publish, and predicted from the code what the probes could not reach. Every claim then went through two judges, who confirmed it, refuted it, or split (CONFIRMED, PLAUSIBLE, REFUTED below). Nothing was edited, deployed or written to a live host. Paths are in this repository unless marked; `open-analytics:` and `open-crm:` prefix paths in the OpenAnalytics and OpenCRM repositories. The personas' notes, the judges' notes and the probe transcripts stayed in the overnight thread's scratch directory, outside the repository. What this read produced is on `main`: #550 (README and user docs), #553 (CLI and agent pages), #551 (starter and skill), #549 (threat-model lines), #552 (public copy), all merged 2026-10-24, and #554 (gateway, HELD for Ben).

The verdict for Monday. The perimeter holds: of 154 anonymous probes, 62 met Cloudflare Access, none produced a 5xx, every control-plane route is behind Access, and the five bypassed prefixes answer exactly what the threat model says (an empty 401 on `/mcp`, two discovery documents with no secrets, 405/401/400 on the token and registration endpoints). The confirmed security findings are low or informational: a stack string inside server-function error bodies (behind Access on the dogfood host, anonymous on a self-host without it), the build stamp in the 404 shell, three documentation sentences that promise more headers than the code sets, and four small scrub misses to fix before the public push. The first user's problems are all in the words and the packaging, and they matter more for Monday than anything the researcher found: the README's four app repositories do not exist publicly yet and none of the four apps has a release, so the "real or vapour" click fails; the new app lands untracked inside the founder's clone and `create` rewrites the root lockfile, so the documented `git pull` aborts on the next upstream lockfile change; three "what does this do to my account" questions (what setup creates, what the Cloudflare login grants, how to remove everything and stop the $5) have no page; the README prompt's exit-code rule loops on two real stops and tells the agent the login is good for 15 minutes when cf gives 5; and the money questions (what "then usage" is, who bills for AI, whether a `.dev` is $1 or $8) are unanswered or unverified. Most of that is a docs PR tonight; the repositories, the prices and the home page are Ben's.

## 2. The researcher's findings

Severity is for a self-hosted alpha with Cloudflare Access in front, which is the launch recommendation and the live shape. Two judges read each finding; CONFIRMED means neither refuted it, PLAUSIBLE means one did (the split is stated), REFUTED means it is in the appendix only. The probe numbers index the probe log kept in the overnight thread's scratch, with a full transcript per probe.

### Ranked

**1. Server-function error bodies carry the error's `stack` string. Low. CONFIRMED (predicted from code, reproduced offline; the judges corrected medium to low).**
Request: `POST /_serverFn/<id>` with `x-tsr-serverFn: true` and `Sec-Fetch-Site: same-origin` and a body that fails validation (`hasOwner` has no auth middleware; `getConsentContext` has a zod validator). On the dogfood host the route is behind Access (probe 67, `GET https://everyapp.team/_serverFn/abc` → 302 to the Access login page), so the reproduction was local: a local script against the gateway's own `seroval@1.6.8`.
Response: `wire: {"t":13,"i":0,"s":0,"m":"Invalid request input","p":{"k":["name","stack","code"],"v":[{"t":1,"s":"PublicError"},{"t":1,"s":"PublicError: Invalid request input\n    at file:///…"}, …]}}`, `has stack key: true`. The ordinary path is HTTP 200 with `X-TSS-Serialized: true`; TanStack serializes the thrown error with seroval, whose default feature set copies every own property, `stack` included (`seroval/dist/index.js:362-379, 945`).
Invariant: `errors.no-internal-leak` (`docs/threat-model-invariants.md:108`) says it "Stops: … stack traces to a browser"; its pinned test (`publicError.test.ts:16-36`) checks the thrown object, not the wire. Not in the Known gaps. What leaks: the `PublicError`'s own frames (`publicError.ts` and the TanStack handler, bundle paths), never the failing code or a secret; the browser maps `code` to a fixed message and never reads `stack`. Behind the outer ring only a member reaches it; a self-host without Access exposes it anonymously.
Fix: `delete err.stack` before throwing (or answer with a `Response` of `{code, message}`) in `apps/every-app-gateway/src/middleware/publicError.ts:11-42`, plus a wire-shape test asserting no `stack` key; note that errors thrown before the middleware (a malformed JSON body) take TanStack's 500 path and are not covered. Gateway code: #554, HELD for Ben, does this for every error the middleware lets out; five server functions (`getEmailStatus`, `getApps`, `getMyApps`, `getActiveOrganization`, `listUserTokens`) never chain it and still send `authMiddleware`'s error with its stack, so adding the middleware first in each chain is the follow-up. Effort S.

Request: probe 102, `GET https://crm.everyapp.team/health` → `200`, `referrer-policy: strict-origin-when-cross-origin`, no `content-security-policy`; probe 9, the control-plane shell → `referrer-policy: no-referrer` and `content-security-policy: frame-ancestors 'none'; base-uri 'self'; object-src 'none'`. Response (trimmed): `<title>Every App</title> … <div … title="Gateway build">1c34d212 · 2026-10-24 06:17Z</div>`.

**4. Case variants of the Access bypass prefixes reach the control-plane 404 shell. PLAUSIBLE: the verifier rates it medium as a confirmed outer-ring bypass; the code judge refuted it as a bypass (the fall-through is the same shell every unclaimed `/.well-known/<x>` gets by design) and rates it info.**
Request: probe 9, `GET https://everyapp.team/MCP` (`--path-as-is`) → `404`, `content-type: text/html`, 2873 bytes, the control-plane shell. Probe 151 `/.WELL-KNOWN/oauth-authorization-server`, probe 152 `/OAUTH/TOKEN` and probe 153 `/MCP/api/auth/get-session` → the identical shell. Contrast: probe 1 `/admin` → 302 to `the Access login page`; probe 19 `/mcp` → `401`, empty body, `www-authenticate: Bearer realm="OAuth", resource_metadata="https://everyapp.team/.well-known/oauth-protected-resource/mcp", scope="mcp:read"`; probe 2 `/mcp/../admin` → Access 302 with `redirect_url=/admin` (the edge normalizes dot segments before Access, not case); probe 15 `/%2e%2e/admin` → Cloudflare 400.
Mechanism: Access's path patterns match case-insensitively; the gateway's `isMcpAuthPath` (`apps/every-app-gateway/src/server.ts:139-143`) and `OAUTH_PATH` (`oauth-flag.ts:56-62`) are case-sensitive, so the variant falls to `serveControlPlane`. ## Method

Two readers, several lanes each, one weekend night, all against `main` at `65fcac70` , the site from a vite dev server at `http://127.0.0.1:5179` (every docs page also as Markdown at its URL with `.md`, plus `/llms.txt` and `/llms-full.txt`), the CLI built in the checkout (`pnpm everyapp`, everyapp 0.3.0, Node 24.20.0, pnpm 10.34.5), the skill at `packages/cli/skills/everyapp`, the starter at `starter/`.

The first user. Five personas read in the order a Monday visitor would: the GitHub README, the home page (source and the served page), the twelve user docs in `content/docs/meta.json` order via `/docs/<slug>.md`, `/docs/agent/index.md` and the agent pages the reading pointed at, `pnpm everyapp --help` and the per-command help, the skill and the starter. T is a solo technical founder with Workers already on a production account, ten minutes, a bias to leave. N is a non-technical founder of a three-person agency, Claude Code installed by a friend, a card, no Cloudflare account, one business domain not to be touched, twenty minutes. C is T at a terminal, running the README block with `pnpm everyapp …` with an empty `XDG_CONFIG_HOME` and no `CLOUDFLARE_*` variables, stdin `/dev/null`, no TTY, so the interactive branches (cf's device login at a terminal, the hidden secret prompt, "No Gateway yet? Type y") were not exercised and are said so wherever it matters ; C also ran every command's `--help` against `cli.md` (31 blocks byte-identical). A is the founder's coding agent, which pasted the README prompt and simulated the run from `agent/setup.md`, `json.md`, `errors.md` and the skill, and ran the docs drift test (35/35). S is T after `pnpm everyapp create my-app`, reading every file `create` left. Each persona graded every moment clear, confusing or stopped and quoted what it read; an editor merged the five into one journey of 70 moments , keeping every stop; 57 confusing or stopped moments became claims M1 to M57, each read by two judges against the checkout with the question "does anything the reader met before this moment answer it, and is the proposed fix right?". Two were refuted; the judges corrected wording, severity and file paths on most of the rest, and those corrections are what this document cites.

The researcher. Five lanes. The map (zero requests) read `apps/every-app-gateway/src/server.ts`, the perimeter, the Access plan in `packages/cli/src/lib/access/plan.ts` and the threat model, and wrote the surface table and a probe plan with a 170-request budget. The probe run made 154 single-threaded, unauthenticated curl requests against `everyapp.team`, `openseo.`, `crm.`, `analytics.` and `agentic-inbox.everyapp.team` and the unresolvable `nope.everyapp.team`, plus two `dig` lookups; every POST body was empty or syntactically invalid; one registration POST at most; never the Access login page; each request's headers and body are saved (a saved transcript per probe (the overnight thread's scratch), index in `probe.log`). Status distribution: 302 × 62, 401 × 35, 404 × 22, 400 × 11, 200 × 10, 204 × 5, 403 × 3, 405 × 2, 308, 307, two DNS failures; no 5xx. The code read (zero requests) predicted from the source and the resolved node_modules what an anonymous caller gets: every error body shape, version strings, source maps, the header floor per surface, CORS, cookies, budgets, logs, the two apps' public routes, and thirteen predicted findings. The public-copy read (zero requests) built the copy with `scripts/public-copy.mjs --no-fetch` into a temporary directory, ran its guard, grepped it rule by rule and read README, SECURITY, LICENSE, `.github` and TODO.md as a stranger. The verifier re-read the saved responses and the source, made exactly one fresh request (`GET https://analytics.everyapp.team/healthz`) and three `dig` lookups, and re-rated each finding; its load-bearing fact, that Access answers every path but the five bypassed prefixes, moved four code predictions. Then two judges per finding (a code-side and a reproduction-side pass) applied one rule: a finding is refuted if it restates a documented gap or design decision, misreads a fail-closed answer, describes Cloudflare's own behaviour, or has no practical consequence for a self-hosted install. CONFIRMED means neither refuted it; PLAUSIBLE means one did; REFUTED items appear only in the appendix. Severities in section 2 are the judges' corrected ones, for a self-hosted alpha with Cloudflare Access in front.

Requests: 154 probes plus 1 verification request (155 HTTP), and 5 DNS lookups. Everything else was read, built or run locally. Scratch files (the seroval probe, the header reproduction, the pnpm and SIGINT reproductions, the built copy) stayed outside the checkout.

Constraints and what was not covered. Read-only throughout: nothing in the checkout was edited, committed or stashed; no deploy; no `cf`, no wrangler against a remote, no Cloudflare API; no `setup`, `login` to completion, `teardown`, `access on`, `delete`, `update` or `install` against the real gateway. No Cloudflare account was used, so the whole authenticated path (setup, the owner link, a real deploy, the `Live`/`Who can open` lines, Access sign-in, consent, refresh-token replay, the member directory, the browser install) is unexercised; the personas' reports of it come from the docs and the code. No authenticated probing, no valid credential sent anywhere, no POST with a valid body, no load or flood (the DCR and waitlist budgets are reasoned, not tested). `everyapp.com` itself, `*.workers.dev`, GitHub's state (the five repositories, private vulnerability reporting, the old tags), npm's state and the registrar's prices were not fetched; those facts come from `TODO.md`, `docs/launch-2026-10-27.md` and the port checkouts' remotes, dated 2026-10-23/24. Postiz is out (not launching). The old `every-*` Workers were not touched. The Access login page was never requested. gitleaks and trufflehog were not run over the copy (not on PATH); the copy's own guard was. The public page `/docs/gateway` was read in both its HTML and `.md` forms where they differ (step numbers). Observed and inferred are separated in every underlying note; where this document quotes a number it did not measure itself (prices, quotas, repository state), it says where the number came from.
