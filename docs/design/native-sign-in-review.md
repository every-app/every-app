Date: 2026-10-27. Branch `feature/native-sign-in` at 7ab315120 (lanes a–d: #861, #860, #859, #858), reviewed independently of the lane threads, against the code rather than the design's claims. Fixes: #862. Design: [native-sign-in.md](native-sign-in.md).

## Checked and found clean

- **Token confusion.** An app-X token on app Y, on the gateway's own routes, at `/mcp`, and an `/mcp` token on app routes are all refused: the library compares the stored audience exactly to the configured resource (ASCII case of scheme and host folded, an empty path equal to `/`, everything else significant), `validateAppHostToken` answers null for an origin not in the list, `boundToAnotherApp` holds the served app's registered hostname to the audience and the app row to the grant's, and both props shapes refuse the other kind's rows. Pinned end to end.
- **Audience canonicalization.** The resource is built from the registry hostname (lowercased, no port) on the issuer's scheme; `appResourceHostname` accepts exactly `<scheme>//<host>` (no userinfo, port, path, query, fragment; host `[a-z0-9.-]`). A client naming `?query` forms is mapped by the library to the canonical resource, so the audience never widens. Trailing dots are stripped from the Host header before matching. Token exchange (RFC 8693) is not enabled, so no cross-audience exchange exists.
- **Consent.** The decision must come from the page's own origin (`Sec-Fetch-Site: same-origin`, else `Origin` equal to the issuer) by a signed-in, unbanned member; the handle is bound to the browser by a `__Host-` cookie and spent once (the row's id derives from it); the form's `resource` is validated against app access before the handle is spent and against the stored request after, so a page for `/mcp` cannot approve an app grant or the reverse; the form's app and access choices count for nothing on a native grant.
- **Resource tampering between authorize and token.** The library refuses a token request whose `resource` is not the grant's (`invalid_target`); omitted, the grant's is inherited. Pinned (a todo grant cannot be exchanged for notes).
- **PKCE and redirects.** S256 required of every client at `/oauth/authorize`; a code without its verifier is `invalid_request`. Loopback matching is anchored (`127.0.0.1.evil.example` is a remote http host and refused), `localhost`/`::1` count as loopback per RFC 8252 (any port, exact path and query), userinfo and fragments are refused when listed, private-use schemes stay off, errors before the client is validated are shown on the page and never redirected.
- **`bearerRoutes`.** The manifest refuses `/`, `/*`, `/**`, `*`, percent-encoding, backslashes, dot segments, the internal namespace, `/mcp` or anything covering it, a path that is also public or a public asset, and more than 25; it runs at author time and at registration. The perimeter matches with the same canonicalization as public routes (encoded separators, double encoding and traversal are ambiguous, never matched); a bearer route wins over a public route or asset on the same path; the gateway's session cookie (both names) is refused there before anything reads it, with or without a bearer; without a bearer the answer is the challenge, never a login page. The Access plan bypasses the bearer paths and the metadata document only on hosts that declare bearer routes, inside the 25-override limit, bearer routes first.
- **Revocation.** The person's revoke, RFC 7009, member removal (row revoked on the way), deactivation, organization suspension, the app's deletion (tombstone revokes native rows; the origin leaves the list) and disabling (audience refused at once; the hourly maintenance revokes the rows), re-consent (superseded by installation and resource), 30 idle days, and the re-joined-member rule all stop the next request; refresh re-checks the row and the app's hostname. Another member's revoke is not found and changes nothing (the server function takes the user from the session, never the request).
- **DCR and names.** The existing per-address and per-gateway daily budgets cover native clients; a dynamically registered name is sanitized (control, format and bidi characters stripped, 80 characters) and marked unverified; a metadata-document client shows its domain, and a loopback redirect counts as covered by it (`domainCoversRedirect`), so the recommended configuration shows no false warning.
- **Identity.** The app sees `chan: "api"`, `act.sub: "oauth:<connection id>"`, `scopes: ["*"]`, the member's `sub`, `org_id` and role; the bearer is stripped from the outbound request; `*` is never granted to an MCP connection even when requested (`scopes_supported` advertises it so the library can approve it).
- **RFC 9728 metadata on app hosts.** Written by the gateway from the registry row before any public route is consulted, only for an active first-party app while `MCP_OAUTH_ENABLED` is on, GET/HEAD; every other discovery document and spelling stays 404; `resource_name` is the manifest's name, JSON-encoded. An app cannot override or poison it.
- **Switches.** `MCP_OAUTH_ENABLED=false` closes issuance, validation on app hosts and the metadata document together; a GATEWAY_URL that cannot be an issuer does the same.
- **Budgets.** An unknown resource re-reads the registry at most every ten seconds; a well-formed-looking token costs one KV read, as at `/mcp`.

## Residual risks

- A stolen access token is good for one app for up to an hour; a stolen refresh token until two refreshes or a revoke (finding 4).
- The perimeter's fail-closed answer on bearer routes relies on the gateway's session cookie names; a future cookie-borne credential must be added to `sessionCookieNames` or it rides through the Access bypass.
- `localhost` is accepted as a loopback redirect host (RFC 8252 allows it; the library's choice); a resolver mapping `localhost` elsewhere is outside the model, as is any process on the device.
- Live run: the review ran in process (SQLite, fake KV); the Cloudflare Access bypass and the real KV are the e2e thread's to confirm.
