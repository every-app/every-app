# Birds brief 4: the Cloudflare Artifacts binding (assumptions)

Written 2026-11-01 on `birds/artifacts-binding`, off main at `1f4382df` (0.3.0-rc.10). The spec is §1.1 of `docs/design/2026-11-birds-forcing-function.md` (branch `birds-forcing-function`), and its decision entry is in `docs/design/2026-11-birds-decisions/forcing-function.md` (branch `birds/decisions-forcing-function`).

Every entry below is **Agent-assumed, pending Ben's review**.

## Verified first

- **The upload API documents the binding.** Cloudflare's OpenAPI spec for `PUT /accounts/{account_id}/workers/scripts/{script_name}` lists `artifacts` in the binding discriminator, as `{ type: "artifacts", name, namespace }` (all three required). The namespace is 2–63 characters matching `^[a-zA-Z0-9]([a-zA-Z0-9._-]*[a-zA-Z0-9._])?$`, and "does not need to be created before binding it". Checked through the Cloudflare API MCP's spec search on 2026-11-01.
- **The toolchain already has it.** `@cloudflare/config` 0.24.1 (the version `cf` 1.0.0-beta.14 pins) has a `{ type: "artifacts", namespace, dev? }` binding and converts it for upload. Miniflare 5's Artifacts plugin is remote-only. `cf` types the binding as `Artifacts` in the generated `Env`. `cf` has `artifacts namespaces repos list|delete` and `artifacts namespaces delete`.
- **The REST API for purge.** `GET …/artifacts/namespaces/{ns}/repos` (limit up to 200, cursor), `DELETE …/repos/{name}` (202, "schedules cleanup of its backing data"), and `DELETE …/namespaces/{ns}` ("Deletes an empty Artifacts namespace").

## Assumptions

**Agent-assumed, pending Ben's review.**

1. **Namespace suffix rule.** The brief says `<worker>--<binding lowercased>`. I used the repository's existing `suffixedName` rule, which also turns `_` into `-` (`AGENT_FILES` → `every-acme-birds--agent-files`), the same as Analytics Engine, Secrets Store and Vectorize. So a binding can't end with `_` (the namespace would end with `-`, which Cloudflare refuses), and the strict schema refuses one.
2. **Length is checked at deploy, not in the schema.** The Worker name is only known at registration, so the 63-character limit is checked in the shared provisioner (`artifactsNamespaces()` in `packages/perimeter/src/install/resources.ts`), before anything is created. It raises `APP_POLICY` with a "shorten the binding" fix. It doesn't get its own error code (Vectorize has `VECTORIZE_NAME_TOO_LONG`), so the docs' error inventory doesn't change.
3. **An existing unrecorded namespace is refused, not adopted.** *(Changed after OpenHack's P3 finding on #900; the first version recorded without asking Cloudflare.)* Before the first record, the deploy looks the namespace up (`findArtifactsNamespace`: `cf artifacts namespaces get`, or `GET …/artifacts/namespaces/<name>` on a Gateway install). One that exists was made by something else (it exists only once a repo was made in it), so it raises `RESOURCE_NAME_TAKEN`, since `delete --purge` would delete its repos. One that doesn't exist is recorded as `kind: "artifacts"` (name and id are both the namespace). A recorded one is bound as it is on later deploys, with no lookup, since it may still hold no repo. There is no atomic claim: a repo someone makes between the lookup and the record is adopted. That window is a moment long, and making a repo needs the account (operator authority, ADR-0003). The ledger's unique `(kind, name)` index still refuses a namespace another app recorded (`RESOURCE_OWNED`). The not-found test for `cf artifacts namespaces get` is part of assumption 6 (unverified live).
4. **A removed binding's row stays.** Like the other kinds, a binding dropped from the manifest isn't forgotten on redeploy, so `delete --purge` still deletes its namespace's repos.
5. **Purge order and failure.** Namespaces are purged after the Workers, with the other data kinds. The purge lists up to 200 repos, deletes each (`--force`), and lists again until nothing new appears (cf prints no cursor), then deletes the namespace. A namespace that was never made (no repo ever created) answers 404, which counts as already gone. If Artifacts refuses (a repo made during the purge), the namespace is kept and reported with `RESOURCES_KEPT`, like a non-empty R2 bucket. The ledger is still cleared, as for buckets.
6. **`--force` on the `cf artifacts … delete` commands.** cf's command list doesn't show the flag for these generated commands, but every other delete wrapper passes it to answer cf's confirmation (`ai-gateway gateways delete`, too). The `cf` JSON output (`repos list` prints the API's `result` array) and the 404 matching (`isCfError(…, "not_found")` through its "not found" text) are from the spec and cf's metadata, **not seen live**. They are the first thing a live check should confirm.
7. **Development is remote-only.** Miniflare has no local Artifacts, so in development the binding is `{ type: "artifacts", namespace: "every-<id>--<binding>", dev: { remote: true } }`, like Vectorize. It works once `remoteBindings` is on, and the repos it makes are real and bill the account. `delete --purge` never reaches the dev namespace (no deploy recorded it). `dev.md` says how to delete its repos by hand.
8. **The Gateway's own install path maps the binding too.** `apps/every-app-gateway/src/server/deploy/self-hosted-metadata.ts` maps `artifacts` to the upload type. Without that, a Gateway app install of an app with Artifacts would pass the shared policy and then fail with `INVALID_BINDING`. The hosted (dispatch) deployer is unchanged: its bundle check refuses any binding type it doesn't list (`MEMORY is a artifacts binding, which third-party apps can't have`, `metadata.ts`), and `manifestTierProblems` refuses `resources.artifacts` on a dispatch row.
9. **`teardown` doesn't delete namespaces yet.** A Gateway teardown (`lib/teardown`) scans by name and kind. Adding Artifacts there is a separate change, so a teardown leaves an app's namespaces and repos. `manifest.md` and the security model say so. Follow-up for Ben to decide.
10. **The security note covers more than TTL and scope.** It also covers the first token `create()` returns, the defaults (scope `write`, TTL a day, max a year), revocation when a member leaves, never logging tokens, and that `import()` has Cloudflare fetch a remote outside the Gateway's egress allowlist. `docs/security-model.md`, "Artifacts".
11. **Dispatch refusal wording.** "Artifacts isn't available to apps in a dispatch namespace yet (its repos would live in, and bill, the platform's account)", next to R2's "yet".
12. **User docs.** One row in `landing-page/content/docs/resources.mdx` ("Git repos", `artifacts`, "Workers Paid, billed by storage and use"). The pricing wording is mine, not checked against Cloudflare's beta pricing page.
