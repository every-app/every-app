## Start from Template

We highly recommend starting from the below template to ensure that everything is configured properly to be deployed on Cloudflare. There are lots of gotchas that have been solved in the template.

<Steps>

1. **Create a new project**

   `every app create`

2. **Name your project**

   Note: this is also what the resources will be called in your Cloudflare account.

3. **Navigate to your project**

   `cd your-project-name`

4. **Start the development server**

   `pnpm run dev`

5. **Navigate to Every App Gateway**

   Go to the Every App Gateway in your browser.

6. **Click "Add App"**

   <Aside type="caution" title="Important">
     The App ID must match your project name or the handshake between the
     gateway and your app won't work.
   </Aside>

7. **Configure your app**
   - Assign a name and description
   - The App URL should be whatever port your dev server is running on (e.g. `http://localhost:3001`)

8. **Test your app**

   Click on your newly created app and you should see a simple todo app template!

</Steps>

## Deployment

Deploy your app to production with a single command:

`every app deploy`

Running this command will:

- Build your code and deploy it to workers
- Create your D1 Database or KV Store if it doesn't already exist
- Run any pending database migrations

## Every App's Role in your App

From the perspective of your application, Every App only does a couple things:

1. Gives your app a session token for authentication
2. Renders your app within an iframe
3. Provides authentication middleware which adds the session token to your request and authenticates the requests on the backend

<Aside type="tip">
  If you're interested in the places where this interaction occurs, take a look
  at everywhere `@embedded-sdk` is referenced. Soon, this will be an npm package
  instead of living inside your app.
</Aside>

## Tech Stack & Helpful Resources

Since Every App is mostly just there for authentication + integrating with the gateway, everything else is up to you! At the end of the day, you're building a web app deployed on Cloudflare.

However, we've picked a couple technologies and done the heavy lifting to make sure they play nice with Cloudflare Workers.

### TanStack Start

This was selected for the following reasons:

- Easy to deploy as a Full Stack app on Cloudflare
- Best out of the box type safety of any framework
- While Tanstack Start is new, the ecosystem is old and trusted.
  - Every tool from TanStack is high quality and becomes my default. They all play extremely nicely together.

Docs: https://tanstack.com/start/latest/docs/framework/react/overview

#### TanStack DB (Client Side Database)

We highly recommend giving this a shot. It makes managing state + optimistic mutations in your application much easier and works incredibly well with TanStack's server functions.

Docs: https://tanstack.com/db/latest

### Cloudflare

This was selected because:

- It's the only hyperscaler with scaling to zero as a top priority.
- They have every cloud component needed to build 99.9% of apps. Crucially, serverless database and container offerings.

Developer Platform Docs: https://developers.cloudflare.com/directory/?product-group=Developer+platform

### Drizzle

Most familiar type-safe ORM.

https://orm.drizzle.team/docs/overview

## Development Workflow

### Install Dependencies

`pnpm install`

### Run Development Server

`pnpm run dev`

### Database Operations

<Steps>

1. **Create a migration**

   Change schema in `src/db/schema.ts`, then run:

   `pnpm run db:generate`

2. **Execute migrations**

   <Tabs>
     <TabItem label="Local">`pnpm run db:migrate:local`</TabItem>
     <TabItem label="Production">`pnpm run db:migrate:prod`</TabItem>
   </Tabs>

3. **View database data**

   <Tabs>
     <TabItem label="Local">`pnpm run db:studio:local`</TabItem>
     <TabItem label="Production">`pnpm run db:studio:prod`</TabItem>
   </Tabs>

</Steps>
