---
title: Add a custom provider
description: Use any API your Gateway doesn't list yet. Describe it in one JSON file and add it with one command.
---

You can add any API that isn't in the [providers list](/docs/providers). Describe it in a small JSON file, and your Gateway holds its key and adds it to calls, like a built-in provider. Apps never see the key.

Your coding agent can write the file from the provider's API docs. Ask it to "add Todoist as a custom provider to my Gateway".

## Add an API with a key

<Steps>
<Step>

### Write the spec

Save a file like this as `todoist.json`:

```json
{
  "id": "todoist",
  "name": "Todoist",
  "description": "Tasks and projects.",
  "docs": "https://app.todoist.com/app/settings/integrations/developer",
  "api": "https://developer.todoist.com/rest/v2/",
  "hosts": ["api.todoist.com"],
  "auth": { "kind": "bearer", "secret": "TODOIST_API_TOKEN" },
  "secrets": [
    {
      "name": "TODOIST_API_TOKEN",
      "hint": "Your API token from Settings → Integrations → Developer."
    }
  ],
  "access": ["read", "write"],
  "readMethods": ["GET"],
  "writeMethods": ["POST", "DELETE"],
  "smoke": {
    "method": "GET",
    "path": "/rest/v2/projects",
    "expect": [200],
    "free": true
  },
  "example": "list my tasks due today"
}
```

| Field                                   | What it is                                                                                  |
| --------------------------------------- | ------------------------------------------------------------------------------------------- |
| `id`                                    | Lowercase letters, digits and hyphens. Apps ask for the provider by it.                     |
| `docs`                                  | Where someone gets the key. Required.                                                       |
| `hosts`                                 | The only addresses the key is ever sent to. No scheme, no path.                             |
| `auth`                                  | How the key is sent: `bearer`, `header`, `query` or `basic`.                                |
| `auth.secret`                           | The name of the setting that holds the key, like `TODOIST_API_TOKEN`. Never the key itself. |
| `access`, `readMethods`, `writeMethods` | What apps may do. `read` allows `readMethods`; `write` adds `writeMethods`.                 |
| `smoke`                                 | Optional: one free call that shows the key works.                                           |

Every field and rule is in [the spec reference](/docs/agent/providers#the-spec).

</Step>
<Step>

### Add it to your Gateway

```bash
everyapp provider add todoist.json
```

It checks the file, shows the hosts the key may go to, and asks for the key. The spec can also be an `https://` URL.

</Step>
<Step>

### Use it in an app

In the app's `everyapp.config.ts`:

```ts
capabilities: {
  todoist: { access: "read", why: "Shows today's tasks on the dashboard." },
},
```

The app calls `https://api.todoist.com/...` with `integrationFetch()`, and the Gateway adds the key. [How apps call providers](/docs/agent/providers#how-an-app-lists-one)

</Step>
</Steps>

`everyapp provider show todoist` shows whether the key is set and which apps use it. `everyapp provider remove todoist` takes it off.

## Add an OAuth provider

For a service where each person connects their own account. Common ones are presets (GitHub, Notion, Linear, HubSpot, Zoom and more):

```bash
everyapp provider presets
everyapp provider add notion-oauth
```

For any other, write a spec with `auth.kind` `"oauth2-user"` and add it with `everyapp provider add --oauth your-spec.json`, or in **Manage workspace → Providers**. The format is in [the OAuth spec](/docs/agent/providers#the-spec-authkind-oauth2-user). How people connect: [Connect accounts](/docs/connect-oauth).

## Remote MCP servers

A service with an MCP server needs no spec. Add it by its URL, and the AI clients connected to your Gateway get its tools:

```bash
everyapp mcp add https://mcp.example.com/mcp
```

More in [MCP apps](/docs/agent/mcp#mcp-apps).
