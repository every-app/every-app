All commands run via `npx everyapp …` (or a local checkout's binary). Global help: `everyapp --help`. The CLI needs Node.js 22.18 or newer and drives Cloudflare's own CLI, `cf`: log in with `npx cf auth login` (the CLI offers it when you're logged out), or set `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.

Deploy commands take `--json` to print progress as NDJSON events on stdout. They exit with 0 when done, 2 when a person has to do something first (log in, open a setup link, buy a domain, confirm in a terminal; run the same command again afterwards) and 1 on an error, whatever came before it. An `action_required` event with `data.waiting: true` is one the command waits for: show its `data.url` (and `data.code`) to a person and keep reading.

## Setup

### `everyapp setup`

One command from an empty Cloudflare account to a working Gateway, its owner, this terminal logged in, and the starter app live. Each step looks at what is there before it acts, so running it again picks up where it stopped, and changes nothing once everything is there:

1. logs in to Cloudflare: `cf auth login` at a terminal (a link and a code), the same link and code as a waited-for `action_required` under `--json`, or `CLOUDFLARE_API_TOKEN` with `CLOUDFLARE_ACCOUNT_ID`;
2. picks the account, and warns when it can't confirm Workers Paid;
3. picks where the Gateway lives: `--domain`, the installed Gateway's address, or (at a terminal) one of the account's domains, suggesting `apps.<domain>`; with no domain on Cloudflare, it says how to buy one and stops (exit 2);
4. deploys the Gateway, or upgrades it to the release this CLI ships, and waits for its certificate;
5. opens a one-time setup link for the owner account (at a terminal; with `--json` it is in the event, except in CI, where setup stops and says to run `npx everyapp gateway claim-link` on your own machine, unless you pass `--printSetupLink`), and once the account exists, logs this terminal in by itself: the link carries a second secret only this CLI keeps, which fetches the owner's first deploy token, once, and it says whose account that is (`Logged in to … as <email> (owner of <organization>)`);
6. copies the starter app (a simple todo list, app `simple-todo`) to `./simple-todo` and deploys it.

| Flag                  | Meaning                                                                                                                      |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `--domain <hostname>` | Where the Gateway lives: any hostname in a zone the account has, e.g. `apps.your-domain.dev`. Asked at a terminal otherwise. |
| `--account-id <id>`   | The Cloudflare account, when your login has several.                                                                         |
| `--dir <path>`        | Where to put the starter app (default `./simple-todo`).                                                                      |
| `--no-starter`        | Set up the Gateway only.                                                                                                     |
| `--allow-free-plan`   | Don't check for Workers Paid (demos; Every App needs it to run).                                                             |
| `--force-dns`         | Publish the Gateway's address even where a DNS record exists (it is replaced) or CAA records would block its certificate.    |
| `--no-open`           | Print the setup link without opening a browser.                                                                              |
| `--printSetupLink`    | Print the setup link even in CI or with piped output, where the log keeps it.                                                |
| `-y`, `--yes`         | Skip confirmations.                                                                                                          |
| `--json`, `--verbose` | NDJSON events; detailed output.                                                                                              |

## Gateway

### `everyapp gateway deploy`

Deploys (or redeploys) your Gateway on your Cloudflare account from the release bundled with the CLI: creates or links its D1 database and KV namespaces, migrates the database (after a Time Travel bookmark it prints with the restore command), binds every deployed app, publishes the Gateway's address and each app's as [Workers Custom Domains](/docs/reference/manage-your-gateway#where-apps-live), uploads the Worker with `cf deploy`, and records the install so later runs keep the address and account. A first deploy generates the Gateway's secrets and sends them with the upload. Before it adds an address, it checks for a DNS record it would replace, CAA records that would block the certificate, and room in the zone (100 Custom Domains), then waits for the new certificate. Deploys never overlap: they take a lease in the Gateway's database. `everyapp setup` runs it for you.

| Flag                  | Meaning                                                                                                                                                                                                                                                         |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--domain <hostname>` | Where the Gateway lives: any hostname in a zone the account has (the longest one that holds it), e.g. `apps.your-domain.dev`. Apps live one level below it. Required the first time; remembered after.                                                          |
| `--account-id <id>`   | The Cloudflare account, when your login has several (default: `CLOUDFLARE_ACCOUNT_ID`, the account used before, or the only one).                                                                                                                               |
| `--release <tarball>` | Deploy this gateway release tarball instead of the bundled one (development).                                                                                                                                                                                   |
| `-y`, `--yes`         | Skip the confirmation prompt.                                                                                                                                                                                                                                   |
| `--printSetupLink`    | Print the one-time owner setup link even when the deploy isn't run from a terminal (CI, piped output). Without it, an unattended deploy of an unclaimed Gateway only tells you to run `npx everyapp gateway claim-link`, so the link never lands in build logs. |
| `--break-lease`       | Take the deploy lease over from a deploy that died (it expires by itself after 10 minutes). Shows who holds it and asks first; unattended, it needs `--yes` too.                                                                                                |
| `--allow-downgrade`   | Deploy a release older than the one the Gateway runs. Releases are ordered by their newest migration, then by when they were built (not by version, which builds share).                                                                                        |
| `--force-dns`         | Publish a new address even where a DNS record exists (it is replaced) or CAA records would block its certificate.                                                                                                                                               |
| `--json`, `--verbose` | NDJSON events; detailed output.                                                                                                                                                                                                                                 |

A Gateway installed before per-app addresses keeps its `*.<domain>` route, and the deploy reminds you if its wildcard DNS record is missing; see [Upgrading an existing install](/docs/reference/manage-your-gateway#upgrading-an-existing-install).

### `everyapp gateway upgrade`

Like `gateway deploy` for a Gateway the CLI deployed before: moves it to the release this CLI ships, with its remembered domain and account. Does nothing when it already runs that release. Same flags.

### `everyapp gateway reconcile`

Makes the live Gateway bind and serve exactly the apps its registry lists, by redeploying the release it runs (fetched from the account's release cache and checked against its SHA-256), so it never upgrades or downgrades the Gateway. It picks that release only once it holds the deploy lease, so it never puts back the release an upgrade just replaced. `app deploy` and `app delete` run it when the set of apps changes. `--dry-run` shows the bindings, the addresses and cf's check without deploying; `--force` redeploys even when nothing changed; `--force-dns` as for `deploy`.

### `everyapp gateway status`

Shows the release the Gateway runs against the one the CLI ships, whether it binds and serves exactly the registered apps, how apps reach it, every address and whether it has its certificate, whether it has an owner, and any deploy in progress.

### `everyapp gateway adopt --domain <domain>`

For a Gateway deployed before everyapp used Cloudflare's `cf` (with the wrangler-era CLI): looks at the account (zone, Worker, namespaces, DNS, migration history, the registered apps), checks that `--domain` serves this account's Gateway (it answers from the version the Worker serves, or, for a Gateway from before that could say, it has an owner exactly when the Gateway's database does; anything else is refused), and records the install as it is, keeping its domain, `*.<domain>` route and app addresses. Nothing is deployed or migrated; run `everyapp gateway upgrade` from a terminal next. `--dry-run` only looks. See [Upgrading an existing install](/docs/reference/manage-your-gateway#upgrading-an-existing-install).

### `everyapp gateway use-per-app-domains`

Moves a Gateway served through its `*.<domain>` route to per-app Custom Domains: every app keeps its address, now published on the Gateway one by one (checked first, as any new address is), and new apps get `<app>.<domain>`. The new routing is recorded only once Cloudflare has published every address: if `cf` stops part-way (a move from another Worker declined at its prompt, the zone's limit, an API error), only the new version is recorded, and running this again finishes the switch. Remove the wildcard DNS record and route afterwards. Flags: `--dry-run`, `--force-dns`, `-y`, `--json`.

### `everyapp gateway claim-link`

Mints a new one-time owner setup link for a Gateway nobody has claimed yet. Any earlier unused link stops working.

### `everyapp gateway secret set <NAME>`

Sets one of the Gateway's optional settings — `OPENAI_API_KEY`, `AI_PROXY_EXTRA_ROUTES`, `EMAIL_REST_API_TOKEN`, `EMAIL_FROM`, `EMAIL_FROM_NAME`, the MCP connector's `MCP_OAUTH_ENABLED`, `MCP_DCR_ENABLED`, `MCP_ALLOWED_ORIGINS` and `MCP_AUDIT_RETENTION_DAYS`, or [Cloudflare Access sign-in](/docs/reference/cloudflare-access)'s `CLOUDFLARE_ACCESS_*` and `EMAIL_PASSWORD_SIGN_IN` — from a hidden prompt or `--from-env <VAR>`, never the command line, and redeploys the live release with it.

## Authentication

### `everyapp login`

Stores a deploy token for your Gateway. Create the token first: **your Gateway → Admin → Tokens → Deploy token** (shown once). The CLI validates it and saves it per-gateway in `~/.everyapp/credentials.json`. Registration and app deploys authenticate with this token. `everyapp setup` does this by itself for the machine that sets the Gateway up.

`everyapp login --resume` finishes the login an interrupted `setup` (or `gateway deploy`, or `claim-link`) was waiting for, once someone created the owner account with its setup link (`--gateway <url>` when several are waiting).

### `everyapp logout`

Removes the stored token for a gateway.

## Apps

App commands find your Gateway from `--gateway <url>`, then `EVERYAPP_GATEWAY_URL`, then the only Gateway you're logged in to.

### `everyapp app create <app-id>`

Scaffolds a new app from the starter template the CLI ships (kebab-case id), wires its `everyapp.config.ts`, deploys it and sets up local development. Flags: `-y`, `--gateway`, `--verbose`.

### `everyapp app deploy`

Run from an app directory. Registers the app with your Gateway, which names its Worker and resources (`every-<org>-<app-id>`) and its address (`<app-id>.apps.your-domain.dev` for your own organization's apps, `<app-id>-<org>.apps.your-domain.dev` for another's); checks a new address (a DNS record it would replace, CAA, room in the zone) before it creates or uploads anything; creates or links the D1/KV resources in `everyapp.config.ts`; migrates its D1 database; builds the Worker that `cloudflare.config.ts` defines (`cf build`) and checks it (private, its own identity keys, no other Workers or resources, and Workflows named after it that no other Worker runs); uploads it with `cf deploy`, which creates or updates its Workflows; has the Gateway bind it and publish its address as a Custom Domain; and waits for a new address's certificate. Redeploying an app's code doesn't touch the Gateway.

| Flag                                   | Meaning                                                                                                           |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `-y`, `--yes`                          | Skip the confirmation prompt.                                                                                     |
| `--access everyone\|admins`            | Who can open a newly registered app (default: the deployer, owners and admins).                                   |
| `--allow-delete-durable-object-data`   | Deploy even though Durable Object classes were removed, deleting their data.                                      |
| `--allow-delete-workflows`             | Deploy even though Workflows were removed, deleting them and their instances once the new version is live.        |
| `--gateway <url>`                      | The Gateway to deploy through.                                                                                    |
| `--force-dns`                          | Publish a new address even where a DNS record exists (it is replaced) or CAA records would block its certificate. |
| `--no-wait-cert`                       | Don't wait for a new address's certificate (it comes within minutes anyway).                                      |
| `--break-lease`, `--json`, `--verbose` | Take over the app's lease from a dead deploy; NDJSON events; detailed output.                                     |

### `everyapp app secret set <NAME>`

Run from an app directory. Sets one of the app's own secrets (an API key its Worker calls out with, say) from a hidden prompt or `--from-env <VAR>`, never the command line, and deploys the app with the secret in the same version, as `everyapp app deploy` does: its code and pending migrations go too, so at a terminal it asks first (`-y` skips that). Later deploys keep it. Setting a secret with `cf` directly makes a version everyapp didn't upload, which the next unattended deploy stops on; this doesn't. Names everyapp sets itself are refused (`GATEWAY_URL`, and the `EVERYAPP_*`, `EVERY_APP_*` and `APP__*` names), as are the app's own binding names. Flags: `-y`, `--from-env`, `--gateway`, `--break-lease`, `--json`, `--verbose`.

### `everyapp app delete [app-id]`

Removes the app from your Gateway (its name and address stay reserved to your organization), drops the Gateway's binding to it and its address, and deletes the certificate Cloudflare keeps for that address. Its Worker and data, and any cron schedules and Workflows the Worker runs, are kept unless `--purge`, which asks you to type the app id and deletes only the Worker, databases and namespaces its deploys recorded creating, with the Workflows that run on that Worker; anything else with its names is kept and listed. Flags: `-y`, `--purge`, `--gateway`, `--json`.

### `everyapp app d1 query "<sql>"`

Runs SQL against the app's production D1 database through `cf`, with your Cloudflare login in the Gateway's account; `--local` queries the database `everyapp dev` uses instead. `--binding` picks a D1 binding other than the migrations one.

### `everyapp app d1 migrate --local`

Applies the app's D1 migrations (`migrations.dir`, default `drizzle/`) to the local database in `.cloudflare/state` that `everyapp dev` serves, with `cf d1 migrations apply --local`. `--json` prints progress as NDJSON events. Used by the `db:migrate:local` package script; production migrations run in `everyapp app deploy`.

### `everyapp app workflows`

Run from an app directory. Manages the deployed app's [Workflows](/docs/how-it-works/sdk#workflows) through `cf workflows`, with your Cloudflare login in the Gateway's account. Name a Workflow by its binding in `everyapp.config.ts` (`RANK_CHECK`), its class or its full name; only a Workflow that runs on the app's own Worker is touched.

| Command                                  | What it does                                                                                 |
| ---------------------------------------- | -------------------------------------------------------------------------------------------- |
| `list`                                   | Each Workflow the app declares, with its instances' counts by status, or "not deployed yet". |
| `instances <workflow>`                   | Its instances; `--status <status>` filters them, `--limit <n>` (1-100, default 25).          |
| `get <workflow> <instance-id>`           | One instance: its status, params, steps, output and error.                                   |
| `start <workflow>`                       | Starts an instance, with `--params '<json>'` and, optionally, its `--id`.                    |
| `pause`, `resume`, `restart` (same args) | Pauses an instance, resumes a paused one, or runs one again from the start.                  |
| `terminate <workflow> <instance-id>`     | Stops an instance for good. Asks first at a terminal; unattended, it needs `-y`.             |

All take `--gateway` and `--json`. Locally, `everyapp dev` links to the Local Explorer, which does the same for the Workflows `cf dev` runs.

### `everyapp app setup-local`

Prepares an existing app checkout for local development (dependencies, `.env.local`, Worker types, local database).

## Local development

### `everyapp dev`

Runs your app under `cf dev` behind a local gateway with the real security perimeter — real identity verification, real public-route policy, hot reload intact. App at `http://<app-id>.localhost:8787`. Before starting it writes the dev identity to `.dev.vars` and applies local D1 migrations. Requires Node.js 22.18 or newer.

| Flag                  | Meaning                                                                                                           |
| --------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `--port <n>`          | Gateway port (defaults to `$PORT`, then 8787).                                                                    |
| `--mode stub\|mirror` | `stub` (default): a seeded dev user, zero setup. `mirror`: real login against a separately running local gateway. |
| `--gateway <url>`     | Mirror mode: the local gateway's URL (default `http://localhost:3000`).                                           |
| `--baseHost <host>`   | Mirror mode: two-label base host for the session cookie (default `everyapp.localhost`).                           |
| `--skip-migrations`   | Skip the local migration preflight that normally runs before the dev server starts.                               |
