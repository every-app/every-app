All commands run via `npx everyapp …` (or a local checkout's binary). Global help: `everyapp --help`. The CLI needs Node.js 22.18 or newer and drives Cloudflare's own CLI, `cf`: log in with `npx cf auth login` (the CLI offers it when you're logged out), or set `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.

Deploy commands take `--json` to print progress as NDJSON events on stdout. They exit with 0 when done, 2 when a person has to do something first (log in, confirm in a terminal, register a workers.dev subdomain; run the same command again afterwards) and 1 on an error.

## Gateway

### `everyapp gateway deploy`

Deploys (or redeploys) your Gateway on your Cloudflare account from the release bundled with the CLI: creates or links its D1 database and KV namespaces, migrates the database (after a Time Travel bookmark it prints with the restore command), binds every deployed app, uploads the Worker with `cf deploy`, and records the install so later runs keep the domain and account. A first deploy generates the Gateway's secrets and sends them with the upload. Deploys never overlap: they take a lease in the Gateway's database.

| Flag                  | Meaning                                                                                                                                                                                                                                                         |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--domain <apex>`     | Your domain (e.g. `your-domain.dev`), a zone on the account. The Gateway serves at it and apps at `<app>-<org>.<domain>` through a `*.<domain>` route. Required the first time; remembered after.                                                               |
| `--account-id <id>`   | The Cloudflare account, when your login has several (default: `CLOUDFLARE_ACCOUNT_ID`, the account used before, or the only one).                                                                                                                               |
| `--release <tarball>` | Deploy this gateway release tarball instead of the bundled one (development).                                                                                                                                                                                   |
| `-y`, `--yes`         | Skip the confirmation prompt.                                                                                                                                                                                                                                   |
| `--printSetupLink`    | Print the one-time owner setup link even when the deploy isn't run from a terminal (CI, piped output). Without it, an unattended deploy of an unclaimed Gateway only tells you to run `npx everyapp gateway claim-link`, so the link never lands in build logs. |
| `--break-lease`       | Take the deploy lease over from a deploy that died (it expires by itself after 10 minutes). Shows who holds it and asks first; unattended, it needs `--yes` too.                                                                                                |
| `--allow-downgrade`   | Deploy a release older than the one the Gateway runs. Releases are ordered by their newest migration, then by when they were built (not by version, which builds share).                                                                                        |
| `--json`, `--verbose` | NDJSON events; detailed output.                                                                                                                                                                                                                                 |

The deploy checks the wildcard DNS record apps need and, if it's missing, prints the one CNAME record to add by hand (once), with a direct dashboard link.

### `everyapp gateway upgrade`

Like `gateway deploy` for a Gateway the CLI deployed before: moves it to the release this CLI ships, with its remembered domain and account. Does nothing when it already runs that release. Same flags.

### `everyapp gateway reconcile`

Makes the live Gateway bind exactly the apps its registry lists, by redeploying the release it runs (fetched from the account's release cache and checked against its SHA-256), so it never upgrades or downgrades the Gateway. It picks that release only once it holds the deploy lease, so it never puts back the release an upgrade just replaced. `app deploy` and `app delete` run it when the set of apps changes. `--dry-run` shows the bindings and cf's check without deploying; `--force` redeploys even when nothing changed.

### `everyapp gateway status`

Shows the release the Gateway runs against the one the CLI ships, whether it binds exactly the registered apps, whether it has an owner, its certificate, and any deploy in progress.

### `everyapp gateway claim-link`

Mints a new one-time owner setup link for a Gateway nobody has claimed yet. Any earlier unused link stops working.

### `everyapp gateway secret set <NAME>`

Sets one of the Gateway's optional settings — `OPENAI_API_KEY`, `AI_PROXY_EXTRA_ROUTES`, `EMAIL_REST_API_TOKEN`, `EMAIL_FROM`, `EMAIL_FROM_NAME` or `MCP_OAUTH_ENABLED` — from a hidden prompt or `--from-env <VAR>`, never the command line, and redeploys the live release with it.

## Authentication

### `everyapp login`

Stores a deploy token for your Gateway. Create the token first: **your Gateway → Admin → Tokens → Deploy token** (shown once). The CLI validates it and saves it per-gateway in `~/.everyapp/credentials.json`. Registration and app deploys authenticate with this token.

### `everyapp logout`

Removes the stored token for a gateway.

## Apps

App commands find your Gateway from `--gateway <url>`, then `EVERYAPP_GATEWAY_URL`, then the only Gateway you're logged in to.

### `everyapp app create <app-id>`

Scaffolds a new app from the starter template (kebab-case id), wires its `everyapp.config.ts`, deploys it and sets up local development. Flags: `-y`, `--gateway`, `--verbose`.

### `everyapp app deploy`

Run from an app directory. Registers the app with your Gateway, which names its Worker and resources (`every-<org>-<app-id>`); creates or links the D1/KV resources in `everyapp.config.ts`; migrates its D1 database; builds the Worker that `cloudflare.config.ts` defines (`cf build`) and checks it (private, its own identity keys, no other Workers or resources); uploads it with `cf deploy`; and has the Gateway serve it at `https://<app-id>-<org>.your-domain.dev`. Redeploying an app's code doesn't touch the Gateway.

| Flag                                   | Meaning                                                                         |
| -------------------------------------- | ------------------------------------------------------------------------------- |
| `-y`, `--yes`                          | Skip the confirmation prompt.                                                   |
| `--access everyone\|admins`            | Who can open a newly registered app (default: the deployer, owners and admins). |
| `--allow-delete-durable-object-data`   | Deploy even though Durable Object classes were removed, deleting their data.    |
| `--gateway <url>`                      | The Gateway to deploy through.                                                  |
| `--break-lease`, `--json`, `--verbose` | Take over the app's lease from a dead deploy; NDJSON events; detailed output.   |

### `everyapp app delete [app-id]`

Removes the app from your Gateway (its name stays reserved to your organization) and drops the Gateway's binding to it. Its Worker and data are kept unless `--purge`, which asks you to type the app id and deletes only the Worker, databases and namespaces its deploys recorded creating; anything else with its names is kept and listed. Flags: `-y`, `--purge`, `--gateway`, `--json`.

### `everyapp app d1 query "<sql>"`

Runs SQL against the app's production D1 database through `cf`, with your Cloudflare login in the Gateway's account; `--local` queries the database `everyapp dev` uses instead. `--binding` picks a D1 binding other than the migrations one.

### `everyapp app d1 migrate --local`

Applies the app's D1 migrations (`migrations.dir`, default `drizzle/`) to the local database in `.cloudflare/state` that `everyapp dev` serves, with `cf d1 migrations apply --local`. `--json` prints progress as NDJSON events. Used by the `db:migrate:local` package script; production migrations run in `everyapp app deploy`.

### `everyapp app setup-local`

Prepares an existing app checkout for local development (dependencies, `.env.local`, Worker types, local database).

## Local development

### `everyapp dev`

Runs your app under `cf dev` behind a local gateway with the real security perimeter — real identity verification, real public-route policy, hot reload intact. App at `http://<app-id>.localhost:8787`. Before starting it writes the dev identity to `.dev.vars` and applies local D1 migrations. Requires Node.js 22.18 or newer.

| Flag                  | Meaning                                                                                                           |
| --------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `--port <n>`          | Gateway port (defaults to `$PORT`, then 8787).                                                                    |
| `--mode stub\|mirror` | `stub` (default): a seeded dev user, zero setup. `mirror`: real login against a separately running local gateway. |
| `--gateway <url>`     | Mirror mode: the local gateway's URL (default `http://localhost:3000`).                                           |
| `--baseHost <host>`   | Mirror mode: two-label base host for the session cookie (default `everyapp.localhost`).                           |
| `--skip-migrations`   | Skip the local migration preflight that normally runs before the dev server starts.                               |
