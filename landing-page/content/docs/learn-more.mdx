What does the Every App CLI do?

</summary>
<div className="faq-content">

The CLI turns your app's configuration into real infrastructure. It provisions databases, storage, and workers on your Cloudflare account, deploys code, and runs your local dev environment, so you never manage that by hand.

```bash
npx everyapp gateway deploy   # Deploy the Gateway to your Cloudflare account
npx everyapp app create       # Scaffold + deploy a new app
npx everyapp app deploy       # Deploy updates to your app
npx everyapp dev              # Run your app locally behind a local gateway
```

Is it really safe to deploy apps an AI wrote?

</summary>
<div className="faq-content">

Yes. Your apps reject any request that doesn't carry a verified identity signed by your Gateway — the SDK checks this at the worker entry, before your code runs, and fails closed. A forgotten auth check in generated code doesn't expose anything, since unauthenticated traffic never reaches app code at all.

The place to stay thoughtful is _within_ your data: making sure one user of your app can't read another user's rows. That's what a security review should check.

Read more: [Architecture](/docs/how-it-works/overview).

</div>
</details>

How does authentication work in apps?

</summary>
<div className="faq-content">

You log into the Gateway; apps never handle credentials. On every request, the Gateway injects a short-lived signed identity token, and the SDK verifies it server-side (`everyApp()` at the worker entry, `requireEveryAppUser` in middleware). Apps have zero client-side auth code.

Read [SDK & App Manifest](/docs/how-it-works/sdk) for the pattern and what's verified.

<summary>

How do I make part of my app public (share links, landing pages)?

</summary>
<div className="faq-content">

Declare the route in `everyapp.config.ts`:

```ts
public: [{ path: "/share/*", methods: ["GET"] }],
```

Public routes skip login and receive `user: null`. Catch-alls like `/*` are rejected when the CLI validates your manifest, so your public surface stays a short, reviewable list.

Read more: [SDK & App Manifest](/docs/how-it-works/sdk).

</div>
</details>

<details className="faq">
<summary>

How do I invite other people to my apps?

</summary>
<div className="faq-content">

Invite them to your Gateway (signup is invite-only after the first account, which is yours). Once they're members, they log into the same Gateway URL and see the apps you've given them access to. Apps create a local user row automatically on first visit; there's nothing per-app to configure.

</div>
</details>

What is the suggested folder structure of an app?

</summary>
<div className="faq-content">

The example apps follow this general layout (individual apps vary):

```
everyapp.config.ts                # App manifest (id, resources, public routes)
src/
├── entry.worker.ts               # Worker entry, wrapped in everyApp()
├── client/                       # Frontend React code
│   ├── components/               # React components
│   ├── hooks/                    # Custom React hooks
│   └── tanstack-db/              # Client-side data layer (collections)
├── db/                           # Drizzle schema + migrations
├── middleware/                   # ensureUser (identity → local user)
├── server/                       # Services and repositories
├── serverFunctions/              # Server functions (RPC endpoints)
└── routes/                       # Pages
```

How do I change my database schema?

</summary>
<div className="faq-content">

Update your Drizzle schema, then generate and run migrations locally (`pnpm run db:generate`, `pnpm run db:migrate:local`). Test in local dev, then deploy — `everyapp app deploy` runs pending migrations in production as part of the deploy. Keep migrations additive when possible.

<summary>

What should my local dev workflow be?

</summary>
<div className="faq-content">

Run `npx everyapp dev` from your app directory and open `http://<app-id>.localhost:8787`. You get hot reload, a local database, and the production auth path (a local gateway verifies identity exactly like the real one). Iterate with your agent, keep commits small, and deploy in thin slices so regressions are easy to isolate.

Details: [Local Development](/docs/build-an-app/local-dev).

</div>
</details>

<summary>

How do I add an environment variable or secret?

</summary>
<div className="faq-content">

Local development reads `.dev.vars`; deployed apps use Cloudflare secrets:

```bash
npx wrangler secret put OPENAI_API_KEY
```

Keep names identical in both places, and never hardcode secret fallbacks in app code.

<summary>

How do I debug a failed deployment?

</summary>
<div className="faq-content">

Identify which phase failed: build, migration, or runtime. Build and migration errors print in the CLI output; runtime errors show in the Cloudflare dashboard logs for your worker. Reproduce locally with `everyapp dev` when you can, and narrow to the most recent change before redeploying.
