> Internal notes for tracking the prototype as it grows — not polished user docs. Verified against code on 2026-07-15.

**The experience in one sentence:** you log in once at the gateway, land on a launcher of app links, and every app is just a subdomain click away — no per-app logins, no tokens, no auth UI inside apps. (Declared-public routes are the one exception: apps may run their own API/webhook auth there.)

## The five journeys

### 1. First person ever (the owner)

1. `everyapp setup` (or `gateway deploy`) prints and opens a one-time link, `/setup#token=est_…` (24h, single use; only its SHA-256 is stored in D1). `everyapp gateway claim-link` re-mints it. Once the claim succeeds, `setup` logs its terminal in by itself (a separate CLI-only secret fetches the first deploy token, once).
2. `/setup` reads the token from the fragment, clears it from the address bar, and asks for name, email and password (8+ chars), which it POSTs as JSON to `/api/setup/claim`.
3. The claim creates the user, their org and the owner membership, consumes the link, and the page signs them in.
4. The home page shows the one live onboarding step: **Deploy your first app** — clone the todo template, `npx everyapp app deploy`, refresh. Completion is inferred from "you have ≥1 app".

Direct sign-up never works: before the claim `/sign-up` shows **Setup pending**, afterwards **Invitation Required**, and Better Auth rejects any HTTP sign-up without a matching invitation server-side (gateway-global, not per-org). Organization creation over HTTP is closed too.

### 2. Returning user

- **Email + password only.** No passkeys, social login, magic links, or SSO.
- If the perimeter bounced you here from an app subdomain, `return_to` sends you back to the full app URL after sign-in (validated: gateway host + subdomains only).
- Forgot/reset password works end-to-end, with non-enumerating responses; owners and admins can also trigger a reset email for a member, or, without email, generate a one-hour single-use reset link to hand over (never for owners, themselves, or anyone who also belongs to another organization, since a password covers every organization; only owners for admins). Reset links point at `/reset-password?token=…`, not a token in the path.
- Auth flows share a Cloudflare CPU-timeout recovery screen (retries up to 10× with countdown — password hashing can blow the free-plan CPU budget).

### 3. Everyday use — the launcher

- Every signed-in page sits in a sidebar: the organization switcher, Home, the Admin pages for owners and admins, settings, and an account menu with the theme and sign out. Home is your app list for the **active org**.
- Clicking an active app navigates same-tab to `//<app>.<gateway-host>`. No iframe, no token handoff — the shared cookie does the work.
- Apps that aren't routable show dimmed with a badge — `needs deploy` when there's no hostname yet, otherwise the raw status (`deploying`, `disabled`).
- Members with zero granted apps are told to contact their admin; owners see deploy instructions instead.
- PWA install lives behind `/pwa` (→ `/?pwa=true`): native prompt on Android, manual instructions on iOS, QR code on desktop.

### 4. Invitations

1. An owner or admin enters an email in **Invite user** and picks the role (`member` or `admin`).
2. The invitation is always created. It's emailed when email is configured; otherwise (or if sending fails) the admin gets a **Copy invite link** (single use, 72 hours) and the Users page shows an "Email not configured" banner.
3. Recipient's link → sign in or create account (email must match the invite — case-insensitive, trimmed).
4. After authenticating, they press **Join organization** — acceptance is a separate explicit step.
5. Membership grants the org's "Available to everyone" apps automatically.

### 5. Admin (`/admin`)

| Page   | What you can do                                                                                                                                                                                                                                                                                                                                                         |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Users  | See members + pending invites in one table; send reset email; change role (member ↔ admin; only owners change admins); deactivate/reactivate (bans the account, ends its sessions, revokes its PATs and deploy tokens); delete user (removes membership and revokes their deploy tokens and PATs for this org; deletes the account only if it belongs to no other org). |
| Apps   | Apps appear only via `everyapp app deploy` — no manual create. Edit name/description/"Available to everyone"; manage per-user access (can't revoke yourself); delete leaves a tombstone that keeps the app id reserved to the org (does **not** undeploy the worker).                                                                                                   |
| Tokens | Create `eak_` deploy tokens (org-wide) and personal access tokens for MCP and API clients; one-time reveal; revoke.                                                                                                                                                                                                                                                     |

**Organizations** (`/organizations`): switch the active org. It's a workspace switcher, not org management — nobody can create, rename or delete orgs (the only org-creating path is the setup claim), and there's no ownership transfer.

**App slugs are organization-scoped:** two organizations can both deploy `todo`. The gateway derives the globally unique routing hostname `<appSlug>-<orgSlug>.<gateway-host>` from the app id and Better Auth organization slug.

## What does NOT exist yet (found while reading)

- **New apps are private** — a first registration grants only the deployer and the org's owners and admins; `access: "everyone"` in the manifest (or `everyapp app deploy --access everyone`) grants every member, and admins can flip "Available to everyone" later.
- **No ownership transfer** — owners and admins can promote members to `admin` (only owners demote admins), but ownership can't move.
- **No invite resend** — pending invites can be cancelled, but there's no resend.
- **No PWA install entry point** — the standalone install modal is reachable only via the `/pwa` URL; there's no button for it (the onboarding step was removed).
