---
title: Sign in through Cloudflare Access
description: Put Cloudflare Access in front of your Gateway, so people sign in with a code emailed to them (or your company login) before they reach it.
---

Optional. Your Gateway already has its own sign-in, and while Every App is alpha we strongly recommend a second one in front of it. Cloudflare Access is that second door, at Cloudflare's edge, from a company that does nothing else: nobody reaches the Gateway or its apps until Access has checked who they are, with a one-time code emailed to them or with your company's identity provider. A bug in the Gateway's sign-in pages then needs someone Access already let in, and a stolen session cookie gets nothing on its own. It takes one command and uses Cloudflare's free Zero Trust plan, which covers 50 people; Cloudflare still asks for payment details the first time, and says it won't charge for the Free plan.

## Turn it on

In your `every-app` folder, run:

```bash
pnpm everyapp access on
```

If your Cloudflare account has no Zero Trust team yet, the terminal asks for a team name. People will sign in at `<name>.cloudflareaccess.com`, and the name can't be changed later, so pick something like your company's name.

If Cloudflare asks you to pick a Zero Trust plan and enter those payment details in its dashboard before the command can create the team, open **Zero Trust** in the Cloudflare dashboard, finish that, and run the command again.

The command then sets everything up and says what it did:

```
Zero Trust team acme.cloudflareaccess.com ✓ created · sign-in through a one-time PIN
Access policy "Every App gateway members" ✓ lets in ben@acme.com and jo@acme.com
Access in front of apps.acme.com ✓ created · MCP and the OAuth endpoints let through
Access in front of *.apps.acme.com ✓ created · public routes of 1 app let through
Gateway settings ✓ CLOUDFLARE_ACCESS_TEAM_DOMAIN, CLOUDFLARE_ACCESS_APPS_AUD, CLOUDFLARE_ACCESS_AUD · one new version

Sign in  https://apps.acme.com
         ben@acme.com and jo@acme.com sign in once with their own password; Access emails them a code first. After that Access alone signs them in.
```

Everyone who is a member, or has a pending invitation, is let in. Anything your apps make public, like a tracking script or a webhook, stays reachable without a login, and so do AI apps connected to your Gateway.

## The first sign-in

The first time, each person opens the Gateway, gets a code by email from Access, and then signs in with their Gateway password as usual. That links the two, and from then on Access alone signs them in. People you invite later never need a password.

Create your owner account and invite people with the email addresses Access will see: the ones your company login or the emailed code uses. An account under a different address can't sign in behind Access.

Once everyone has done that, you can turn passwords off:

```bash
pnpm everyapp secret set EMAIL_PASSWORD_SIGN_IN
```

Enter `false`: Gateway settings like this one are set with the same command as secrets, and the prompt says what each takes. Nothing changes until an owner has signed in through Access, so it can't lock you out.

## When you invite someone

Run `pnpm everyapp access on` again after inviting someone, so Access lets them in too. Nobody is ever removed from Access this way: to take someone off, [deactivate them](/docs/people#remove-someone) in the Gateway, which signs them out everywhere at once.

To let everyone with an email at your company through Access, run it with your domain:

```bash
pnpm everyapp access on --email-domain acme.com
```

They still need an invitation to get an account, unless you also let people at that domain join on their first sign-in: `pnpm everyapp secret set CLOUDFLARE_ACCESS_AUTO_JOIN_DOMAINS`, and enter the domain.

## Check it, or turn it off

```bash
pnpm everyapp access show
pnpm everyapp access off
```

`show` lists the team, who is let in and whether everything is in step. `off` asks first, then takes Access off: passwords sign people in again at once. The team and its settings stay in your Cloudflare account.

## Good to know

- Deploying an app keeps its public routes reachable: `pnpm run deploy` tells Access about them.
- An Access sign-in lasts 30 days by default. For a daily code, run `pnpm everyapp access on --session 24h`.
