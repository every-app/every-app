---
title: Update an app
description: Ship changes to an app, keep your Gateway up to date, remove apps you don't need, or remove everything.
---

## Ship a change

In the app's folder, deploy again:

```bash
pnpm run deploy
```

The app's data stays.

## When the app stores something new

If a change affects what the app saves, like a new field on a todo, the database needs a migration. Your coding agent usually writes it. If not, run this in the app's folder:

```bash
pnpm run db:generate
```

Without one, the deploy stops with **The schema has changes no migration covers** before changing anything.

## Undo a database change

Before a deploy changes an app's database, it saves a restore point. To go back to it, run this in the app's folder:

```bash
pnpm everyapp db restore
```

It asks first. Anything saved in the app since that deploy is lost too.

## Update your Gateway

To get the newest Gateway, run this in your `every-app` folder:

```bash
git pull
pnpm install
pnpm everyapp update
```

Your people, apps and data stay, and if Cloudflare Access is in front it is brought in step with the new Gateway on the way (what it lets through without a login, the ways to sign in). The apps you made in `apps/` are yours, not EveryApp's: git neither tracks nor ignores them, and `git pull` leaves them alone. If it stops with **Your local changes to the following files would be overwritten by merge: pnpm-lock.yaml**, run `git checkout -- pnpm-lock.yaml` and pull again: creating an app rewrote that file, and `pnpm install` adds your app back to it.

When there's an update to take, `pnpm everyapp status` says **Your every-app folder has a newer Gateway than the one online**. That isn't a problem: your Gateway keeps working until you update it. Deploying a new app from the newer folder updates the Gateway on the way; deploying an app again never touches it.

## Remove an app

```bash
pnpm everyapp delete my-app
```

This takes the app off your Gateway. Its data is kept.

Add `--purge` to delete its data too. This can't be undone, so it asks you to type the app's name first.

## Remove everything

There's no command for this yet. To take EveryApp out of your Cloudflare account, or to start again at a different address:

1. Remove each app while the Gateway is still there: `pnpm everyapp delete my-app --purge` (above).
2. If you turned Cloudflare Access on, run `pnpm everyapp access off`. [Check it, or turn it off](/docs/access#check-it-or-turn-it-off)
3. In the Cloudflare dashboard, delete three things: under **Compute & AI**, then **Workers & Pages**, the Worker `every-app-gateway` (its address goes with it; if a DNS record is left at that name, delete it under your domain, then **DNS**); under **Storage & Databases**, the D1 database `every-app-gateway` and the KV namespace `every-app-gateway-OAUTH_KV`.
4. To stop the $5 a month, open [Workers plans](https://dash.cloudflare.com/?to=/:account/workers/plans) and change to the Free plan. Your domain renews on its own, at Cloudflare's price.

Everything else in your account stays as it was. Setup keeps no record of the Gateway on your computer and finds one only by its D1 database, so once that is gone, `pnpm everyapp setup` with the new address installs a fresh one: you create your owner account and invite people again, and deploy each app again from its folder.
