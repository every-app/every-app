The Gateway's admin UI (**Manage workspace** in the sidebar: Users, Groups, Apps, Tokens, Usage, Activity, Events, plus AI connections in the account menu) is one of three ways to run a workspace. The other two are for agents:

| Surface                                                  | Who acts                                                                                                                                           | Authority                                                                                                                                                                                                                                                                                                               | Where it shows                                                                                   |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `pnpm everyapp workspace …`, `pnpm everyapp call <tool>` | the person, through the tools below: `EVERYAPP_TOKEN` (a personal access token) or the browser sign-in `pnpm everyapp login --gateway <url>` keeps | exactly the tools' (each command is one of them, run through the Gateway's own services). The exceptions are `workspace reset-link` (the recovery link) and `workspace invite-link` (an invite link), written into D1 under the Cloudflare login, since no tool returns a link (ADR-0003 in the checkout, `docs/adr/`). | one row in Admin → Activity per call, client `everyapp-cli`                                      |
| `everyapp_workspace_*` tools on `https://<gateway>/mcp`  | the person behind an OAuth connection, a personal access token (`epat_`) or a Cloudflare Access assertion                                          | their live role in the organization (re-read on every request) and the connection's access. A tool is hidden below its role; a write tool is hidden from, and refused for, a read-only connection like any app write tool. The services' own rules apply on top and come back as tool errors.                           | one row in Admin → Activity per call, app `everyapp`, with the client's name, like any tool call |

Every row of the parity matrix (which UI action is which command and which tool, and the few with none) is in the checkout at `docs/design/2026-10-agent-parity.md`; a test (`packages/cli/src/docs/parity.test.ts`) fails when a UI action gets no twin and no reason.

## The CLI: `everyapp workspace`

Each command is one of the tools below, run as you through the Gateway's admin API (`packages/cli/src/lib/gatewayApi`): its flags become the tool's arguments, the tool's answer is the `done` event's `data` under `--json` ([the protocol](/docs/agent/json)), and every rule is the Gateway's. `pnpm everyapp call <tool> [json]` runs any tool by name, apps' tools too, and `pnpm everyapp call --list` lists them.

**As whom.** `EVERYAPP_TOKEN` set to a personal access token (Manage workspace → Tokens; read-only or one-app tokens see what they would on `/mcp`), else the sign-in `pnpm everyapp login --gateway <url>` stored in `~/.config/everyapp/gateways.json` (0600), else that sign-in now: the browser opens at the Gateway's consent page (under `--json` its URL is in a `gateway.signin` progress event and the run waits). Choose read & write and all apps there: a grant narrowed to some apps sees no workspace tool. `pnpm everyapp login --gateway <url> --sign-out` revokes and forgets it. **Which Gateway.** `--gateway <url>`, else `EVERYAPP_GATEWAY_URL`, else the one Gateway this machine signed in to, else the one the Cloudflare login finds (`--account-id`, or `--gateway <name>` among several). A refusal is `GATEWAY_TOOL_ERROR` with the Gateway's code in `data.code`; a refused credential `GATEWAY_REFUSED`.

`--yes` skips the confirmation of `remove` and `group delete`. People are named by email or user id, apps by their manifest id (`crm`) or row id, groups by name or `grp_` id, invitations by the invited email or id.

## The MCP tools: `everyapp_workspace_*`

Listed on the Gateway's `/mcp` to owners and admins beside `everyapp_list_apps`, `everyapp_whoami` and `everyapp_search_tools` ([the connector](/docs/agent/mcp#the-connector-httpsgatewaymcp)). A member sees none of them and a call answers "Unknown tool". A read-only connection sees the read tools only. A credential narrowed to apps (a personal access token bound to one app, a connection consented for selected apps) sees none of them: it administers nothing. They are listed in the full listing; in the compact listing (a connection past 256 tools or 1 MiB, or `X-EveryApp-Tools: compact`) a client finds them with `everyapp_search_tools` and runs them through `everyapp_call_read` or `everyapp_call_write`, like app tools. Every call leaves one row in Admin → Activity.

Four tools are for every member, about their own things: `everyapp_my_tokens` and `everyapp_revoke_token` (the caller's personal access tokens, never a value), `everyapp_my_connections` and `everyapp_revoke_connection` (the caller's AI connections in every organization; revoking the one in use ends it on the next request).

Rules every tool holds (`toolbus.workspace-tools-role-gated` and `toolbus.workspace-tools-no-credentials` in the threat model's register):

- No tool returns a credential that opens the Gateway: no invite link, no password-reset link, no token value. None creates a personal access token: a connection that can be revoked must not mint itself a credential that outlives it. The UI does those; the CLI, a client of these tools, does neither, but for its two links under the Cloudflare login (`workspace reset-link` and `workspace invite-link`). The one secret a tool returns is the webhook signing secret `everyapp_workspace_events_add` generates, once: it opens nothing on the Gateway.
- A refusal is a tool error, `CODE: message`, with the UI's codes (`OWNER_REQUIRED`, `CANNOT_MANAGE_SELF`, `CANNOT_MANAGE_OWNER`, `USER_IN_OTHER_ORGANIZATION`, `USER_NOT_FOUND`, `APP_NOT_FOUND`, `INVALID_INPUT`); a tool hidden by role or access is not listed and is "Unknown tool" on call, so a member learns nothing about them.
- `remove`, `app_delete` and `mcp_remove` are an owner's or admin's (since 2026-10-25; nothing on the connector is owner-only) and take `confirm: true`; `events_remove` takes it too; without it they refuse and say so. What stays an owner's is inside the services: an admin never removes an owner (`OWNER_REQUIRED`), never makes or demotes one.
- The arguments are checked against each tool's own schema whatever their size, and every call is audited with an argument digest and a byte count, never the arguments themselves.

## Which to use

- An agent at a terminal: the CLI, signed in once (`login --gateway`) or with `EVERYAPP_TOKEN`. It is the same tools.
- An agent connected as a person (claude.ai, Claude Code, Cursor, a script with a personal token): the tools, with that person's role.
- Creating a personal access token, copying an invite or reset link, approving an AI app's connection: the UI, by the person. Under the Cloudflare login the operator also gets an invite link (`workspace invite-link`) and, locked out of the Gateway, the way back in (`workspace reset-link`).
