The Gateway's admin UI (**Manage workspace** in the sidebar: Users, Groups, Apps, Tokens, Usage, Activity, Events, plus AI connections in the account menu) is one of three ways to run a workspace. The other two are for agents:

| Surface                                                 | Who acts                                                                                                  | Authority                                                                                                                                                                                                                                                                                     | Where it shows                                                                                                                      |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm everyapp workspace …`                             | the operator: the Cloudflare login (or `CLOUDFLARE_API_TOKEN`) that owns the Gateway's account            | root. The commands write the Gateway's D1 directly, like `email set` and `provider on` (ADR-0003 in the checkout, `adr/`), with the same guards the UI holds: never the last owner, never an owner by an admin. Nothing is asked of the Gateway over HTTPS, so they work while it is down.    | the next request to the Gateway reads the change; nothing is written to Admin → Activity (Cloudflare's audit log has the D1 writes) |
| `everyapp_workspace_*` tools on `https://<gateway>/mcp` | the person behind an OAuth connection, a personal access token (`epat_`) or a Cloudflare Access assertion | their live role in the organization (re-read on every request) and the connection's access. A tool is hidden below its role; a write tool is hidden from, and refused for, a read-only connection like any app write tool. The services' own rules apply on top and come back as tool errors. | one row in Admin → Activity per call, app `everyapp`, with the client's name, like any tool call                                    |

Every row of the parity matrix (which UI action is which command and which tool, and the few with none) is in the checkout at `docs/design/2026-10-agent-parity.md`; a test (`packages/cli/src/docs/parity.test.ts`) fails when a UI action gets no twin and no reason.

## The CLI: `everyapp workspace`

Run from anywhere, with `--json` when an agent drives it ([the protocol](/docs/agent/json)). Every command takes `--gateway` and `--account-id`, and all but `rename` and `role` take `--org <slug|id|name>`; without it a command acts on the install organization (the one the first deploy made). `--yes` skips the confirmation of `remove` and `group delete`. People are named by email or user id, apps by their manifest id (`crm`) or row id, groups by name or `grp_` id, invitations by the invited email or id.

| Command                                                                                                                                                                | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `workspace show`                                                                                                                                                       | The organization (name, slug, id), its owners, whether the Gateway can send mail, and counts of members, pending invitations, groups and apps.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

| `workspace invite <email> [--role admin]`                                                                                                                              | Create the invitation (good for 72 hours) and print its link (`https://<gateway>/accept-invitation?token=einv_…`). The CLI never mails it: hand the link over. The invitation records the operator as its inviter, so the operator's login email must be a verified member (`WORKSPACE_NOT_A_MEMBER` otherwise).                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `workspace invite-link <email\|id>`                                                                                                                                    | A new link for a pending invitation; earlier links keep working until it is used, canceled or expires.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `workspace uninvite <email\|id>`                                                                                                                                       | Cancel a pending invitation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `workspace role <email> <owner\|admin\|member>`                                                                                                                        | Change a member's role. An owner is made or demoted only by the operator or, in the UI, by an owner; the last owner can never be demoted.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `workspace rename <name>`                                                                                                                                              | Rename the organization (the slug, and so every Worker name, stays).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `workspace deactivate <email>`                                                                                                                                         | Ban the account: no sign-in, every session ended, personal access tokens and AI connections revoked, in one batch. Never the last live owner.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `workspace reactivate <email>`                                                                                                                                         | Lift the ban. Revoked tokens and connections stay revoked.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `workspace remove <email>`                                                                                                                                             | Remove the membership, their app grants, group memberships, tokens and connections in this organization, and the account itself when it belongs to no other organization. Like the UI, someone Cloudflare Access would let straight back in is deactivated instead (decided from whether an Access auto-join setting is set, since its value is a secret the CLI cannot read; the output says how to delete anyway). | `workspace reset-link <email>`                                                                                                                                         | A one-hour, single-use password-reset link to hand over (`https://<gateway>/reset-password?token=…`), for a member of this organization alone and not deactivated. Unlike the UI it works for an owner: the operator is root, and this is how a sole owner who lost their password gets back in. Mailing one is the UI's or the MCP tool's.                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `workspace groups`                                                                                                                                                     | The groups with member and app counts.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `workspace group create <name> [--description]`, `workspace group set <group> [--name] [--description]`, `workspace group delete <group>`                              | A group's name is unique in the organization. Deleting a group takes its app grants with it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `workspace group members <group> [--add <email>…] [--remove <email>…] [--set <email>…]`                                                                                | Who is in the group; or change it. `--set` replaces the whole list.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `workspace group apps <group> [--add <app>…] [--remove <app>…] [--set <app>…]`                                                                                         | Which apps the group opens; or change it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `workspace apps`                                                                                                                                                       | Every app of the organization with who can open it (everyone, or how many people and groups), its setup state and status. `status` is the operator's view of the same apps (Workers, versions); this is the admin's.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `workspace app set <app> [--name] [--description] [--everyone on\|off]`                                                                                                | The catalog entry: the name and description people see, and whether every member can open it. Turning `--everyone off` keeps the people who already have access.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `workspace app access <app> [--add <email>…] [--remove <email>…] [--set <email>…]`                                                                                     | Who can open the app directly (groups grant it too); or change it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `workspace app cap <app> <n\|off>`                                                                                                                                     | The organization's monthly cap on the app's provider calls (a whole number up to a billion); `off` removes the app's own cap. Once the workspace default exists (the Caps thread's PR), `off` inherits it and `--unlimited` means no cap at all; `workspace cap default <n\|off>` sets the default for every app without its own. The semantics are the Usage page's (Manage workspace → Usage). An app past its cap is refused with `app_monthly_cap_exceeded`. As in Admin → Usage, the organization's first cap makes the built-in Cap alerts subscription (owners and admins emailed at 80% and at the cap; `pnpm everyapp events list` shows it, `done.data.capAlerts` names it the run it is made), and a cap set, raised or removed queues `cap.raised` (a lowered one doesn't). |
| `workspace usage [--month YYYY-MM]`                                                                                                                                    | What the organization's apps spent in a UTC month: per app, per member and per provider, with each app's effective cap and where it comes from once the default exists.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `workspace activity [--app <app>] [--user <email>] [--decision allowed\|blocked] [--risk read\|write\|destructive] [--since <time>] [--limit <n>] [--before <cursor>]` | The tool-call audit trail, newest first: who called which tool of which app, through which client, allowed or blocked, and the outcome; the Activity page's filters, and `--before` takes the previous page's cursor (`done.data.nextBefore` under `--json`). Never the arguments or the result.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `workspace tokens [--user <email\|id>] [--all]`                                                                                                                        | Personal access tokens: name, scopes, app, expiry, last use; `--all` lists revoked and expired ones too. Never a value. The operator sees every member's.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `workspace token revoke <id>`                                                                                                                                          | Revoke one. The next request with it is refused.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `workspace connections [--user <email>]`                                                                                                                               | AI connections (the OAuth clients people connected): client, access, apps, last use.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `workspace connection revoke <id>`                                                                                                                                     | Revoke one.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

What the CLI does not do, and why: it cannot create a personal access token (the Gateway hashes tokens with `BETTER_AUTH_SECRET`, a Worker secret the CLI never holds; create one in Admin → Tokens), and it sends no mail (the Gateway's sender does; the CLI prints links instead). `everyapp delete <app>` removes an app's Worker and catalog row, so there is no `workspace app delete`.

## The MCP tools: `everyapp_workspace_*`

Listed on the Gateway's `/mcp` to owners and admins beside `everyapp_list_apps`, `everyapp_whoami` and `everyapp_search_tools` ([the connector](/docs/agent/mcp#the-connector-httpsgatewaymcp)). A member sees none of them and a call answers "Unknown tool". A read-only connection sees the read tools only. A credential narrowed to apps (a personal access token bound to one app, a connection consented for selected apps) sees none of them: it administers nothing. They are listed in the full listing; in the compact listing (a connection past 256 tools or 1 MiB, or `X-EveryApp-Tools: compact`) a client finds them with `everyapp_search_tools` and runs them through `everyapp_call_read` or `everyapp_call_write`, like app tools. Every call leaves one row in Admin → Activity.

Four tools are for every member, about their own things: `everyapp_my_tokens` and `everyapp_revoke_token` (the caller's personal access tokens, never a value), `everyapp_my_connections` and `everyapp_revoke_connection` (the caller's AI connections in every organization; revoking the one in use ends it on the next request).

Rules every tool holds (`toolbus.workspace-tools-role-gated` and `toolbus.workspace-tools-no-credentials` in the threat model's register):

- No tool returns a credential that opens the Gateway: no invite link, no password-reset link, no token value. None creates a personal access token: a connection that can be revoked must not mint itself a credential that outlives it. The CLI and the UI do those. The one secret a tool returns is the webhook signing secret `everyapp_workspace_events_add` generates, once: it opens nothing on the Gateway.
- A refusal is a tool error, `CODE: message`, with the UI's codes (`OWNER_REQUIRED`, `CANNOT_MANAGE_SELF`, `CANNOT_MANAGE_OWNER`, `USER_IN_OTHER_ORGANIZATION`, `USER_NOT_FOUND`, `APP_NOT_FOUND`, `INVALID_INPUT`); a tool hidden by role or access is not listed and is "Unknown tool" on call, so a member learns nothing about them.
- `remove` and `app_delete` are owner-only and take `confirm: true`; `events_remove` is an owner's or admin's and takes it too; without it they refuse and say so.
- The arguments are checked against each tool's own schema whatever their size, and every call is audited with an argument digest and a byte count, never the arguments themselves.

## Which to use

- An agent on the operator's machine (the one that ran `setup`): the CLI. It needs no account on the Gateway except to invite.
- An agent connected as a person (claude.ai, Claude Code, Cursor, a script with a personal token): the tools, with that person's role.
- Creating a personal access token, copying an invite or reset link, approving an AI app's connection: the UI, by the person.
