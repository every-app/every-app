EveryApp has two sets of documentation. The [user docs](/docs) are short and written for the person: set up Cloudflare, get a domain, install the Gateway, create an app, invite people. These pages are the other set: complete references written for the coding agent (Claude Code, Codex, Cursor) that does the work and answers the person's questions. Most people never read these pages; their agent does.

## If you are the person

Give your agent this address and ask it anything about EveryApp:

```text
https://everyapp.com/llms.txt
```

New apps come with two skills, `everyapp` (drives the CLI; it already points here) and `build-every-app` (how to build or change an app the way the four open apps do), under `.agents/skills/<name>` and `.claude/skills/<name>`.

## If you are the agent

1. Fetch `https://everyapp.com/llms.txt`: every page with a one-line summary, in both sets.
2. Fetch the page you need as Markdown by adding `.md` to its URL, for example `https://everyapp.com/docs/agent/manifest.md`. Everything in one file is `https://everyapp.com/llms-full.txt`; prefer single pages.
3. In an EveryApp checkout the same pages are files: `landing-page/content/agent/*.md`, the user docs `landing-page/content/docs/*.mdx`, and the repository documents under `docs/` that the `repo/` pages mirror.
4. Answer from the page, with the exact command, flag or manifest field, and name the page. When a command fails, look up its code on [errors](/docs/agent/errors) (the anchor is the code) before trying anything else.
5. The command line tool is `everyapp`: `npm install -g everyapp`, then `everyapp …` (in a checkout of the EveryApp repository, `pnpm everyapp …`). Add `--json` when you drive it, and read [the protocol](/docs/agent/json). `everyapp dev` is the exception: long-running and human-facing, no `--json`.

## Two sets of docs, one rule

The user docs (`landing-page/content/docs`) hold what a person does with their own hands (the Cloudflare account, the domain, the owner link, the hidden prompt of `secret set`, inviting people, connecting an AI client) and each command as one line, with no flag beyond the one a person types (`landing-page/content/docs/commands.mdx`). Short, no codes. These pages (`landing-page/content/agent`) hold everything else: every flag, code, field, pattern, limit and the reasoning behind it, and the playbooks ([Driving setup](/docs/agent/setup), [Everything a Gateway offers](/docs/agent/gateway), [Build an app](/docs/agent/build)). The rule for a new fact: a step only the person can take goes in the user docs, in a sentence, and the agent page says why and what every field means; anything else goes here alone. The agent docs may repeat a user-doc step with its reasons; the user docs never carry an agent-doc fact.

## Setup skills

Step-by-step setups an agent follows for the person, one file per integration, shipped with the everyapp skill (in the checkout `packages/cli/skills/everyapp/setup/`, in an app `.claude/skills/everyapp/setup/` and `.agents/skills/everyapp/setup/`; the index is `setup/README.md`): `gateway.md` (Cloudflare account, Workers Paid, domain, login, setup, owner claim, status as the check), `access.md` (`everyapp access on|off|show`), `email.md` (Cloudflare Email Sending or Resend, `EMAIL_FROM`, `email set`), `dataforseo.md`, `context.md`, `openrouter.md`, `openai.md`, `workers-ai.md` (API keys: where the key comes from, plan, exact secret name, smoke check), `google.md`, `microsoft-365.md`, `slack.md` (OAuth clients: console steps, redirect URI, scopes, the secret by pipe), and `providers.md` (generated from the catalog: every catalog provider under its id, with its settings, where the key comes from, how it is sent and a smoke request; a provider registered on one Gateway has no file, `pnpm everyapp provider show <id>` prints its spec). The setup files say what to do; these pages say why and what every field, flag and code means. Beside the everyapp skill ships the build skill, `build-every-app` (in the checkout `packages/cli/skills/build-every-app/`, in an app `.agents/skills/build-every-app/`): how to build or change an app the way the four open apps and the starter do, with its patterns index; served here as [Build an app](/docs/agent/build) and [Example patterns](/docs/agent/patterns).

## What to tell the person

EveryApp is open source, very powerful, alpha, and moving fast; the team tries not to break things, and a deploy saves a restore point before it changes a database. It is built for a solo founder or a three-to-four person startup that wants its own apps on its own Cloudflare account. For a company's Gateway, recommend [Cloudflare Access](/docs/agent/access) in front of it.

## Keeping these pages true

The CLI reference is generated from the commands, [Build an app](/docs/agent/build) and [Example patterns](/docs/agent/patterns) from the build skill, and a test in `packages/cli/src/docs` fails when a page misses a command, flag, error code, manifest field, Gateway setting, header, SDK export, built-in tool or Admin tab the code defines. The `repo/` pages are mirrored from `docs/` at build time. Edit the rest in `landing-page/content/agent/`.
